# FileMonitorTool

一个常驻 Windows 系统托盘的文件监控小工具：监视你指定的文件夹，等新文件“落盘稳定”后，自动执行你配置的动作（复制、解压、归档、转码、调用外部程序……）。

基于 `FileSystemWatcher` + 去抖（Debounce）实现，整个程序没有主窗口，双击托盘图标即打开配置。

## 特性

- **多文件夹同时监控**：`[Folder:名字]` 节想写几个写几个，每个文件夹有自己的规则，也能单独覆盖子目录、监听修改、去抖窗口
- **只对新文件动手**：默认只关注新放入 / 改名进来的文件，不理会内容修改（可通过 `WatchChanged` 打开）
- **去抖合并事件**：复制大文件时 Windows 会连发几十个事件，静默 `DebounceMs` 毫秒后才触发一次
- **文件就绪检测**：触发前用独占读句柄试打开，仍被占用则自动延迟重试，避免处理半截文件
- **多规则分流**：一条规则由「条件后缀」+「`.command`」组成，条件可按扩展名、文件名、完整文件名三选一或组合，按书写顺序决定优先级，第一条命中即生效
- **全局兜底规则**：写在 `[Global]` 里的规则，只有各文件夹自己的规则都不中时才会用到
- **并发有上限**：`MaxConcurrentActions` 限制同时执行的动作数，一次落盘几百个文件也不会瞬间炸出一堆进程
- **配置有校验**：结构性错误（缺 `[Global]`、`[Folder:x]` 缺 `Path`、布尔或数字非法、键值写在节外）直接拒绝启动，日志与托盘气泡写明原因；单条规则写错（漏 `.command`、条件为空、未知后缀、规则名带点、与保留键同名）只跳过该条；某个文件夹路径不存在则跳过它、其余照常
- **动作模板**：命令支持 `{filepath}` `{filename}` `{basename}` `{directory}` `{ext}` `{timestamp}` 占位符
- **执行有兜底**：`.exe` / `.com` 直接启动（避开 cmd 的引号剥离），其余交给 `cmd /c`；单次执行 10 分钟超时会被结束，标准输出、错误输出与退出码都写进日志
- **配置热重载**：改完 `config.ini` 保存，右键托盘 → “重新加载配置”即可生效，无需重启
- **可随时暂停**：托盘菜单有“停止监控 / 开始监控”开关，暂停期间不再处理新文件，程序仍常驻；重载配置会保持当前的运行或停止状态
- **图标随状态切换**：运行中是程序图标，停止监控后托盘换成“已停止”图标，托盘提示文字同步显示“运行中 / 已停止”，一眼就能看出当前状态
- **开机自启**：托盘菜单勾选即可，写入 `HKCU\...\CurrentVersion\Run`，不碰管理员权限
- **日志轮转**：单个日志超过 1 MB 自动转存为 `.1`
- **单实例**：命名互斥体防重复启动

## 使用

1. 运行 `FileMonitorTool.exe`。程序目录下没有 `config.ini` 时会自动生成一份带完整注释和示例的配置，托盘出现图标即开始监控。
2. 右键托盘 → “打开配置文件”，按下面的说明改 `config.ini`：先给要监控的文件夹写 `Path`，再往里加规则。
3. 保存后右键托盘 → “重新加载配置”即可生效。

托盘菜单：打开配置文件 / 重新加载配置 / 打开日志 / 停止监控（或开始监控）/ 开机启动 / 退出。点“停止监控”后图标换成停止样式，再点“开始监控”恢复。

> **从 1.4.x 升级到 1.5.0**：规则写法变了——旧版的 `规则名=扩展名列表`（不带后缀）不再被识别，会在日志里报“缺少后缀”并跳过该规则。请先把旧的 `config.ini` 删掉（或改名留档），让程序重新生成新模板，再把文件夹与规则按新写法抄回去。`IncludeSub` / `WatchChanged` / `DebounceMs` 这些键名没变。

> **从 1.3.x 及更早版本升级**：配置格式已整体更换，旧的 `config.ini`（顶层的 `WatchPath`、`FileFilter`、`Action.<N>.Ext` 等写法）不再被识别，程序会报“配置错误”。请先删掉旧的 `config.ini`（可改名留档），让程序重新生成新格式，再把原来的目录和规则按新写法填回去。

## 配置结构

配置文件是纯文本，用「节」组织：

```ini
[Global]
IncludeSub=false
WatchChanged=false
DebounceMs=300

[Folder:下载]
Path=D:\down
Zip.ext=zip;rar;7z
Zip.command="D:\Tools\UniExtract\UniExtract.exe" "{filepath}" /sub
```

- 以 `#` 或 `;` 开头的行是注释，空行忽略
- 所有键值都必须写在某个节内；写在 `[Global]` 之前会直接报错
- 同一节内的同一个键只能出现一次，重复时只有最后一行生效并记一条告警

### `[Global]`（必需）

| 配置项 | 说明 | 默认 |
| --- | --- | --- |
| `IncludeSub` | 是否递归监控子目录，可被文件夹节覆盖 | `false` |
| `WatchChanged` | 是否响应“已有文件内容被修改”，可被文件夹节覆盖 | `false` |
| `DebounceMs` | 去抖窗口（毫秒，最小 10），可被文件夹节覆盖 | `300` |
| `MaxConcurrentActions` | 同时执行的最大动作数（小于 1 按 1 处理），只能全局设置 | `4` |
| `LogUnmatched` | 没有命中任何规则的文件是否记一条日志，只能全局设置 | `true` |
| `LogFile` | 日志文件，相对路径基于程序目录，只能全局设置 | `monitor.log` |

`[Global]` 里除上面这些保留键之外的裸键，都会被当作**全局规则**解析，写法与文件夹内规则相同。

### `[Folder:名字]`

每个要监控的文件夹写一个节，`名字` 自取，用于日志与气泡显示。节内保留键：

| 键 | 说明 |
| --- | --- |
| `Path` | **必填**，监控目录的绝对路径；目录不存在时该文件夹被跳过，其余继续运行 |
| `IncludeSub` | 可选，覆盖全局的同名设置 |
| `WatchChanged` | 可选，覆盖全局的同名设置 |
| `DebounceMs` | 可选，整数且 >= 10，覆盖全局的同名设置 |

### 规则

节内其他键都是规则。一条规则 = 若干条件 + 一个动作，基础名相同的一组键属于同一条规则（基础名不能含 `.`，也不能和保留键同名）：

```ini
# 条件：至少写一个，可自由组合
Admin.name=*行政专员*              # 按文件名匹配（不含扩展名）
Doc.ext=doc;docx;xls;xlsx          # 按扩展名匹配（去点、小写；可写 pdf、*.pdf、d*）
Rep.fullname=报表*.docx;*.tar.gz   # 按完整文件名匹配（含扩展名）

# 动作：必填
Admin.command=move /Y "{filepath}" "D:\Archive\行政专员\{filename}"
```

- 条件后缀三种：`.ext` 扩展名、`.name` 文件名（不含扩展名）、`.fullname` 完整文件名（含扩展名）
- **同一维度多个值用分号分隔，命中任一即可；不同维度之间必须同时满足**
- 三种条件都支持 `*` 与 `?` 通配符，整串锚定、不区分大小写
- `.fullname` 用于把扩展名写进模式的场合（多段扩展名 `*.tar.gz`、`报表*.docx` 这类）；它和 `.ext` / `.name` 同时写时**以 `.fullname` 为准**，并在日志里给一条提示
- 优先级严格按**书写顺序**：越靠前越优先，第一条命中就停止（同一条规则以最早出现的那行为准）；兜底规则务必放最后
- `command` 里 `.exe` / `.com` 直接启动，其余（内置命令、`%VAR%`、重定向、`.bat`）交给 `cmd /c`
- 占位符：`{filepath}` 完整路径、`{filename}` 文件名（含扩展名）、`{basename}` 文件名（不含扩展名）、`{directory}` 所在目录、`{ext}` 扩展名（不带点）、`{timestamp}` 形如 `20261109_143012`（提交动作时生成一次）

**会被点名的问题**：缺 `.command`、条件全空、未知后缀（如把 `X.ext` 写成 `X.doc`）、规则名含 `.`、与保留键同名，都只跳过该条并记日志；某个文件夹 `Path` 不存在只跳过该文件夹；一条有效规则都没有时托盘弹“没有有效规则”。

**典型用法：文件名带关键词就归类**

```ini
# 下载目录里，文件名含“行政专员”的一律移到归档目录，其余按扩展名分
Admin.name=*行政专员*
Admin.command=move /Y "{filepath}" "D:\Archive\行政专员\{filename}"

Install.ext=exe;msi
Install.command=move /Y "{filepath}" "D:\Archive\安装包\{filename}"
```

## 编译

- Visual Studio 2022（17.10 及以上，`.slnx` 解决方案格式）
- 或命令行：`dotnet build -c Release`（需要 .NET Framework 4.8 目标框架包），也可以直接双击仓库里的 `编译.bat`

目标框架 `net48`，使用 WinForms；输出在 `bin\Release\net48\`。

```

```

## 说明

- 只支持 Windows（依赖 WinForms、注册表、`FileSystemWatcher`）。
- `Command` 最终会变成真实进程，配置即代码，请勿使用来路不明的配置。
- 若动作程序需要 UAC 提权（Win32 错误 740），工具本身不会提权，日志里会给出对应提示。
- 监控网络盘或超大目录时，`FileSystemWatcher` 内部缓冲区可能溢出，日志中会出现相应告警；可缩小监控范围或关闭子目录监控。
